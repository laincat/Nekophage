# 桌面端接 Magpie:复用本机安装版

[English](MAGPIE-DESKTOP.en.md) | 简体中文

本文是接入评估与首个客户端实现的记录。用户已明确首期直接使用本机安装的 Magpie。Windows/macOS 为主要平台,Linux/Web 只预留接口。目标仍是复用供应商及其他插件,按需求、难度、订阅期限与额度等条件在多个供应商/模型之间路由。

## 首期架构与责任

Nekophage 作为 Magpie 的客户端,连接它已有的本地网关。Magpie 继续管理插件、运行时、供应商账号、登录刷新、模型目录与路由。首期不在 Nekophage 里重建插件宿主或复制一套供应商凭据。

| 部分 | 责任 |
|---|---|
| Nekophage | 连接设置、连通性/能力检查、选择模型或路由组、发送任务、流式结果与取消、中文错误提示 |
| 本机 Magpie | 原版插件执行与管理、供应商登录和刷新、账号选择、已支持的策略/分组/回退、用量与路由记录 |
| 操作系统 | 用户正常安装和启动 Magpie;Nekophage 首期不接管其安装、升级或进程生命周期 |

主界面继续 MyGo。插件页面、面板、菜单等交互先在 Magpie 自己的界面中使用;通过网关调用到插件能力,不等于这些 UI 已经嵌入 Nekophage。需要插件工具时,还要核对 Magpie 对外提供的 MCP/工具接口和调用权限,不把所有插件都当成模型接口。

iOS 仍需在 App 内融入 Magpie 插件、账号及多供应商路由能力并独立运行,不是转为桌面网关客户端;完整路由和各类插件兼容尚待补齐。桌面复用安装版的决定不缩减 iOS 目标,也不增加“必须有一台桌面 Magpie”这一前置依赖。Linux/Web 将来可提供相同的连接接口实现,但浏览器跨域、部署和凭据存储不在首期验收范围。

## 已核查的接口与未验证事项

以下来自本地 Magpie 参考源码,尚未对用户机器上的实际安装版本做连通测试。实际版本的接口和能力以探测结果为准。

| 项目 | 参考实现 | 接入方式 |
|---|---|---|
| 地址 | 默认 `127.0.0.1:3425`,可由设置或 `MAGPIE_ADDR` 改变 | 设置页默认 `http://127.0.0.1:3425`,允许用户改端口;路径拼接统一处理,避免重复 `/v1` |
| 模型目录 | `GET /v1/models` | 读取网关实际公开的模型与组 ID,保留原 ID,不把组拆回单一供应商 |
| 推理 | `POST /v1/chat/completions`、`/v1/responses`、`/v1/messages` | 首期按任务选择并验证一种协议;工具、推理、图像字段另做保真测试 |
| 本机身份 | 参考源码有本机 token `magpie` 与 `magpie-<agent>` | 结合实际版本验证;该本机标识不是供应商密钥,也不等于远程访问的安全凭据 |
| 状态/记录 | 参考实现有 `/v1/magpie/*` 用量/路由相关接口 | 可选能力,按版本探测;首期可先在 Magpie 界面查看,不依赖其内部 GUI `/api/*` |

默认只连本机。远程地址涉及共享设置、真实网关密钥与传输安全,不随首期本机接入自动启用。若用户配置网关密钥,才使用 Windows DPAPI/macOS Keychain 保存该密钥;供应商凭据继续由 Magpie 管理。不得通过读取 Magpie 私有配置或凭据文件来绕过公开接口。

## 需求与路由怎样衔接

Nekophage 把任务送往用户配置的模型或路由组,由 Magpie 完成其已有的候选选择和故障处理。避免两边各自重试、各自换供应商,造成重复请求或费用。

| 用途 | 首期方式 | 仍需核实的边界 |
|---|---|---|
| 按需 | 配置任务类型到 Magpie 模型/组的映射,或显式选择 | 模型能力、上下文和工具支持以实际目录与请求验证为准 |
| 按难度 | 简单/普通/复杂档位映射到已有路由组;若 Magpie 已配置分类规则,直接调用对应组 | 不假设每个版本都自动识别难度;复杂分类规则留在 Magpie 管理 |
| 按额度与可用性 | 复用 Magpie 已有的额度、冷却、回退和账号策略 | 不把未知额度当成无限;具体策略取决于安装版及插件报告 |
| 按订阅到期 | 先核对安装版是否已有所需策略或可用策略插件 | 已有到期展示字段不代表支持“即将到期优先用”;token 到期、额度重置、积分失效与订阅结束不能混用 |
| 插件扩展 | 在 Magpie 安装启用,从网关/MCP 或它自己的界面使用 | 不宣称所有插件功能自动出现在 Nekophage 界面中 |

示例:“复杂任务”映射到一个 Magpie 强模型组,组内的排序由 Magpie 配置。若确需“优先用即将到期且还有额度的套餐”而安装版没有该能力,单列为后续策略插件/上游扩展工作;不在初期连接适配中悄悄另造路由器。流式输出开始后,Nekophage 不自行切换模型拼接答案;取消应关闭当前请求,并验证 Magpie 上游工作随之停止。

## 已实现:客户端连接层

`internal/magpie` 已可连接网关,并有对假网关的契约测试;**尚未接入界面,也尚未对真实安装版验证**。

| 文件 | 状态 | 内容 |
|---|---|---|
| `internal/magpie/client.go` | 已实现 | 地址归一化(裸 `host:port` 补 scheme)、协议选择、本机标识头、状态码到中文诊断的映射、SSE 事件解码(三种方言) |
| `internal/magpie/models.go` | 已实现 | `GET /v1/models` 解析,保留模型与路由组 ID,空目录不是错误 |
| `internal/magpie/chat.go` | 已实现 | 按协议构造原生正文、流式取回、`ctx` 取消、流中断与半途错误上报 |
| `internal/magpie/config.go` | 已实现 | 连接设置(地址、协议、本机标识)与任务档位映射的读写:原子写入、损坏文件报错而不重置、档位拼错直接拒绝、空档位回落到显式模型 |
| `internal/magpie/*_test.go` | 已实现 | 假网关契约、配置与会话测试共 24 条;另有 5 条窗口逻辑测试(档位去向提示、越界保护、空档位不写入、中文标签、模型预览长度):`-race` 通过;覆盖目录、三种方言、`[DONE]`、无终止标记、流内错误、取消、鉴权/404/未启动诊断、地址校验,以及设置往返、缺文件、损坏文件、错误档位、空档位回落 |
| `internal/ui/magpie.go` | 已实现 | 「AI」窗口:填地址并测试连接、读取模型目录、填模型名、发一条任务并边收边显示、可取消;回包按 80ms 节流重绘,不为每个 token 重画窗口。任务档位可选简单/普通/复杂,每个档位填一个模型或组,空档位回落到默认模型,再没有就交给 Magpie 的默认路由;窗口上方直接显示「这次会发到哪」 |
| `internal/ui/app.go` | 已实现 | 顶栏「AI」按钮;窗口单例,设置存 `magpie.json` |
| 真实安装版探测 | 未做 | 还没有对用户机器上的 Magpie 发起过请求 |

首期无需新增 Core 路由包、Bun IPC、插件包安装器、供应商登录或完整路由编辑器。原先 28–55 日的“自建宿主与路由”预算不再适用于本期;该方案只作为以后脱离外部安装版时的独立评估方向。

## 工作量与验收

粗估 **4–8 个开发日**完成基本连接适配与一个实际任务入口,不是交付承诺,不含新增 AI 产品功能、缺失的订阅策略、所有 MCP/插件页面整合或等待用户账号授权的时间。若现有协议不能保留任务所需的工具/多模态字段,要单独扩展估算。

| 阶段 | 粗估 | 验收 |
|---|---|---|
| 本机安装版探测 | 0.5–1 日 | 确认实际地址、版本/可探测能力、模型和组、鉴权行为 |
| 客户端与契约测试 | 1.5–3 日 | 模型发现、请求、流式、取消,覆盖未启动/拒绝访问/流中断 |
| 设置与任务映射 | 1–2 日 | 保存连接配置、选组、简单/复杂任务落到预期组;不复制 Magpie 路由 |
| Windows/macOS 实测 | 1–2 日 | 两端从 Nekophage 发出实际请求,在 Magpie 对照供应商选择、路由记录和取消行为 |

验收必须包含实际跨供应商/账号的选择和失败回退,不能仅看 `/v1/models` 返回成功。涉及费用的实际请求使用用户选定的模型和账号;凭据不进入日志。已安装但未运行时给出“请启动 Magpie/检查网关地址”的诊断,不擅自重装、升级或启动持久服务。

## 后续边界

用户已选择首期复用本机 Magpie,不再要求重选“嵌入 Bun 还是自建宿主”。实施时先读取或探测实际安装环境,只有缺少具体连接信息才询问用户。插件、账号和路由规则继续在 Magpie 中管理。待实际验证后,再决定是否增加状态面板、MCP 工具适配、订阅期限策略或内置部署。
